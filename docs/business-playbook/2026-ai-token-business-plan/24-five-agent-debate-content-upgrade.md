# 24. 五小工十轮 debate 后的内容与销售落地升级包

Date: 2026-06-14

目的：把 5 个小工的输出合并成一套可以直接执行的内容、材料、表格、私信推进和复盘审核方案。重点不是再多写几句战略，而是让每一条内容都能落到：

```text
标题
画面材料
表格字段
示例数据
私信关键词
承接产品
下一步动作
复盘指标
合规边界
```

本文件是 22 号和 23 号文档的升级补强包。22 号解决“每天怎么拍、怎么发、怎么复盘”，23 号解决“三条内容线有什么素材”。本文件解决“5 个小工 debate 后，哪些内容先做、怎么分流、怎么报价、怎么避免空洞和违规”。

## 0. 五个小工分工

| 小工 | 角色 | 负责判断 | 最终贡献 |
|---|---|---|---|
| 小工 A | 企业/财务/采购线 | 老板、财务、采购到底关心什么 | 采购比价表、开票信息表、29,800/98,000 配置审查表 |
| 小工 B | 技术/API/模型路由线 | OpenAI-compatible 接入、BYOK、路由、试跑指标是否具体 | 接入交付单、模型路由决策树、7 天 API 验收表、脱敏清单 |
| 小工 C | 电商/出海线 | 电商客户用不了大包时，低价任务怎么交付 | SKU 资料表、标题 SEO 表、FAQ 表、短视频脚本表、出海 listing 多模型表 |
| 小工 D | 投流增长/短视频线 | 公域内容如何从播放走到私信、试用、报价 | 五阶段漏斗、首 7 天排期、AB 测试表、内容复盘表 |
| 小工 E | 销售转化/合规线 | 私信怎么分流、报价怎么推进、什么话不能说 | 线索评分表、报价推进表、合规审稿表、20 条私信话术 |

最终统一结论：

```text
不要公开卖“便宜 token / 额度 / key”。
对外只卖“企业 AI 用量托管 + 电商 AI 内容服务 + 出海 API/模型路由 + 合同/普票/专票 + 用量报表 + 预算控制”。
低成本供给只是内部成本优势，不能当公开视频和销售话术的核心卖点。
```

## 1. 十轮 debate 结论

### Round 1：到底卖 token，还是卖服务

争议：

```text
技术线觉得客户会先问 API 和额度。
销售/合规线认为公开讲低价 token、半官方渠道、共享 key 风险太高。
企业线认为 B2B 客户真正付钱是为了合同、发票、报表、预算和责任边界。
```

胜出结论：

```text
对外不卖 token。
对外卖企业 AI 用量托管、API 接入管理、电商内容工作流和出海模型路由。
```

修正动作：

```text
所有标题删除：半官方、内部渠道、最低价、无限量、不封号、共享 key。
所有海报底部加：不卖共享账号/共享 key，不承诺 ROI/GMV/排名，企业可走合同、普票/专票和用量报表。
```

### Round 2：内容主结构用三条线，还是五阶段漏斗

争议：

```text
23 号文档已经按企业/财务、技术/API、电商/出海三条线拆了。
增长线认为只按内容线拆会导致“看完知道你懂，但不知道下一步私信什么”。
```

胜出结论：

三条内容线继续保留，但发布和销售必须套进五阶段漏斗：

| 阶段 | 目标 | 内容任务 | CTA |
|---|---|---|---|
| 引流 | 让目标客户停下来 | 预算失控、发票、API key 风险、电商素材浪费、投流烧钱 | 评论/私信关键词 |
| 信任 | 证明你懂交付 | 展示预算表、日报、路由表、SKU 表、报价排除项 | 发送 demo 表格 |
| 试用 | 降低首单门槛 | 9.9/39/99/399/2,980 的边界 | 平台内表单/服务 |
| 报价 | 推进中客单 | 2,980/4,980/9,800/29,800 配置卡 | 发配置卡 |
| 大单 | 铺垫 98,000+ | 采购流程、合同、发票、月报、复盘、验收 | 企业需求表 |

修正动作：

```text
每条内容必须标注所属漏斗阶段。
每条内容只设置 1 个主关键词、1 个主承接产品、1 个降档方案、1 个升级方案。
```

### Round 3：低价体验能不能强推

争议：

```text
增长线认为 9.9 容易引流。
财务线认为 9.9 线索可能低质。
销售线认为 9.9 如果没有升级 SOP，就只是忙。
```

胜出结论：

9.9 可以做，但只能当“受控体验”，不能当“裸额度包”。

具体边界：

| 体验项 | 建议配置 | 风险控制 |
|---|---|---|
| 9.9 受控体验 | 1 天，1 个场景，最高 USD 30 面值预算，后台控制 | 不导出 key，不支持批量，不支持文件上传，不支持团队共享 |
| 19.9 API 连通体验 | 1-2 天，1 个工具连通性测试 | 只测连接，不做生产接入 |
| 39 单品快写 | 1 个 SKU，标题 3 版、卖点 5 条、FAQ 5 条 | 表单下单，1 次轻修改 |
| 2 元邀请券 | 仅限渠道邀约或活动补贴 | 不公开卖，不作为长期产品 |

重要利润提醒：

```text
如果 USD 30 面值的内部成本仍高于 9.9，9.9 就是获客补贴，不是利润产品。
9.9 的考核指标不是毛利，而是有效线索率、升级到 399/2,980 的比例、合规风险是否可控。
```

### Round 4：标题要不要追求“很吸睛”

争议：

```text
增长线想要强钩子。
合规线反对“最低价、爆单、稳赚、官方、内部”这类强刺激。
电商线认为标题必须让客户知道能拿到什么。
```

胜出结论：

标题优先级：

```text
第一，有具体痛点。
第二，有具体材料。
第三，有明确客户类型。
第四，不承诺结果。
第五，能承接私信关键词。
```

禁止标题方向：

```text
最低价 AI token 怎么买
内部渠道便宜额度
保证爆单的 AI 文案
不封号 API key
9.9 无限用
```

可用标题方向：

```text
公司买 AI 前，先把“谁用、用多少、谁付、谁管”说清楚
API key 不该出现在前端代码里，技术负责人必须检查这 5 处
商品资料不全时，AI 写出来的不是文案，是猜测
投流前，不要只问预算，先填素材测试表
29,800 增长包不是买额度，是买管理
```

### Round 9：私信推进必须从关键词升级成评分

争议：

```text
增长线已经有“预算/API/电商/发票/出海”等关键词。
销售线认为只有关键词不够，必须打分，否则容易把时间花在低价围观客户上。
```

胜出结论：

所有私信按“关键词分流 + 3 问 + 线索评分 + 推荐档位”推进。

每个关键词的 3 问：

| 关键词 | 3 问 | 初始标签 |
|---|---|---|
| 预算 | 几个人用，月预算大概多少，是否需要发票/合同 | 企业/预算 |
| API | 现成工具还是自研系统，是否已有官方 key，是否进入生产系统 | 技术/API |
| 电商 | 平台、SKU 数、最卡的是标题/客服/短视频/SEO 哪块 | 电商/任务卡 |
| 发票 | 普票还是专票，付款主体是谁，是否需要合同 | 企业/财务 |
| 出海 | 平台/国家/语言，是否 BYOK，是否含客户个人信息 | 出海/API |

评分区间：

```text
0-3 分：发公开资料或 demo，不重点跟进。
4-7 分：推 39/99/199/399 低价任务或诊断。
8-12 分：推 2,980/4,980 试用包。
13-17 分：推 9,800 轻托管/出海模型包。
18 分以上：进入 29,800/98,000 正式报价池。
任一红线命中：不报价，先合规拒绝或升级审核。
```


```text

能带 29,800 报价：拆成系列内容。
触发合规风险：立即停拍和改写。
```

## 5. 私信推进话术，按步骤走

### 5.1 问价

```text
价格看场景，我先不直接报，避免你买错。
你回我 3 个信息：
1. 做电商内容、API 接入、客服，还是团队用量？
2. 个人、小店，还是公司团队？
3. 需不需要合同、普票或专票？

我按情况给你推荐档位。
```

### 5.2 嫌贵

```text
贵通常有两种情况：
一种是确实不需要这么大范围；
一种是需要，但预算还没确认。

我们可以先把范围降下来，只保留一个核心场景。
不做批量、不做团队支持、不做报表，就从低档开始。
不建议直接砍价，优先降范围。
```

### 5.3 要免费试

```text
可以看 demo 样例，但免费样例只展示结构，不处理真实商品/API/客户数据。
只要涉及你的真实 SKU、真实接口、真实客户资料或正式交付，就需要走付费诊断或体验包。
这样边界更清楚，也避免后面扯皮。
```

### 5.4 要 API key

```text
我们不提供共享 API key，也不做裸 key 倒卖。
企业接入通常有两种：
1. 你们自带官方 key，我们做 BYOK 路由、预算和报表；
2. 按合同范围交付经授权的企业接入信息。

体验包不导出 key。
```

### 5.5 要发票

```text
可以支持普票/专票，具体开票项目按实际服务内容和财务口径确认。
你先发我：
付款主体、开票主体、税号、普票还是专票、是否需要合同。

我再判断适合从 2,980/4,980 试用，还是正式包开始。
```

### 5.6 电商小店

```text
电商小店不用一上来买大包。
你先告诉我平台、类目、SKU 数、最卡的是标题/卖点/客服/短视频/SEO 哪一块。
如果只是一个商品，39/99 就够。
如果是一批上新，再看 199/999。
如果每月持续上新和复盘，再考虑 4,980 或 9,800。
```

### 5.7 电商要承诺 GMV

```text
GMV、ROI、排名和爆单不能承诺。
我们能交付的是标题、卖点、脚本、FAQ、素材测试计划和复盘表。
最终经营结果还受商品、价格、供应链、投放、店铺权重和平台规则影响。
```

### 5.8 出海 API

```text
出海 API 我先确认 5 件事：
目标国家/平台、语言、使用场景、是否已有官方 key、是否进入生产系统。
我们优先建议 BYOK，也就是你们自带官方 key，我们做模型路由、预算和报表。
```

### 5.9 29,800 报价前

```text
你们这个已经不是单次体验，更像团队用量管理。
我报价前需要确认：
几个人用、核心场景、月预算、是否要合同发票、谁决策、谁验收、本月是否启动。
确认后我发配置卡和正式报价。
```

### 5.10 收口成交

```text
我这边下一步给你两个选择：
A 是低风险试用，先验证一个场景；
B 是正式配置卡，走合同、发票和预算管理。

你回复选 A 还是 B，我按对应资料清单推进。
```
