# 04. 销售运营

## 销售原则

不赊账、不垫资、不口头锁定、不打裸价格战。服务采用预付，因为上游模型调用会产生实时成本。可以提供普票和专票，但开票项目必须与实际服务内容一致，不能把开票当作规避服务实质的手段。

## 销售漏斗

| 阶段 | 定义 | 下一步 |
|---|---|---|
| 新线索 | 评论、私信、表单或直播线索 | 5 分钟内回复 |
| 已联系 | 客户回答核心问题 | 询问诊断信息 |
| 已筛选 | 用例、预算或用量明确 | 预约诊断 |
| 已诊断 | 完成 10–20 分钟沟通 | 2 小时内报价 |
| 已报价 | 正式报价已发出 | 24 小时内确认 |
| 签约中 | 套餐、主体、发票已确认 | 发合同和付款信息 |
| 已付款 | 到账 | 开通并建支持群 |
| 服务中 | 服务运行 | 周报和续费提醒 |
| 续费/流失 | 升级、续费或流失 | 记录原因 |

每条 CRM 记录必须有“下一步动作 + 负责人 + 时间”。

## 首次私信

```text
你是想先算 AI 用量成本，还是已经有接口/团队，需要稳定调用和管控？我先不报价，先问 5 个问题，避免你买多或买错。
```

## 五个诊断问题

1. 你现在主要用 AI 做什么？
2. 每月大概花多少钱，或每天多少请求量？
3. 是个人用，还是公司团队/产品调用？
4. 更关心便宜、稳定、发票、权限、速度，还是售后？
5. 谁决定付款？本周要上线，还是先了解？

## 成交复述

```text
我先复述一下：你现在不只是缺 token，而是要解决三个问题：
第一，月用量要可控，不能突然超预算；
第二，要能对公付款和开票；
第三，要有人帮你把接口、限额、报表和续费看住。
所以我不建议你买零散小包。建议先从适合你当前用量的试跑或增长包开始，跑 30–60 天，数据稳定后再升级团队包。
```

## 常见异议

### “太贵了”

```text
如果只是比裸用量价格，直接找官方或最低价渠道会更便宜。我们收的是企业托管服务费：对公、发票、预算上限、用量报表、异常预警、续费提醒和技术支持。如果预算紧，可以先做受控试跑，不建议为了低价买不稳定渠道。
```

### “我再想想”

```text
可以，给你两个判断标准：如果你本月用量低于 3,000 元，先不用买我们的服务；如果本月预算超过 1 万，或者需要发票和团队管理，就值得评估托管包。我在约定时间再跟进，你只需要回复做或不做。
```

### “别人更便宜”

```text
你可以比较计费口径：模型、输入输出、上下文长度、是否含税、是否有发票、预算上限和售后响应。如果这些都一样且更便宜，选对方没问题；如果不一样，别只看单价。
```

### “能不能后付款？”

```text
AI 用量是实时消耗成本，我们不能垫资。但可以做小额试跑包，跑通后再升级，试跑数据也能作为你内部审批依据。
```

## 付款与开票流程

1. 创建 CRM 记录；
2. 完成需求诊断；
3. 确认套餐、服务主体和发票信息；
4. 发送报价和合同；
5. 收到对公或合规平台付款；
6. 开通服务并发送接入说明；
7. 按实际服务内容开具电子发票；
8. 设置用量和续费提醒。

## API 接入交付

付款并确认套餐后，向客户发送 OpenAI-compatible 接入说明，包含：Base URL、脱敏记录中的客户 API Key、模型名、流式支持、预算上限、限流规则、允许场景、支持联系人和敏感数据提示。生产接入前先用非敏感提示词测试 `/chat/completions`。

不要在公开代码、前端页面、截图或仓库中展示完整 API Key；不要要求客户通过聊天发送密码、Cookie 或上游私钥。

## 试跑边界

低价试跑仅用于验证连接和一个业务场景，设置固定期限、用量上限、并发限制和异常自动停止，不导出共享 API Key，不支持无限量或批量任务。正式生产使用应以书面授权、合同、数据边界和实际成本核验为前提。
