# 04. Sales Operations

## Sales Rule

No receivables. No advance funding. No verbal lock-in. No raw low-price battle.

The service is prepaid because upstream usage creates real-time cost.

Commercial advantage: ordinary VAT invoices and special VAT invoices are both available. Use this to qualify enterprise customers and justify the service package, but never present invoice issuance as a workaround for unclear service substance.

## Sales Funnel

| Stage | Definition | Next Step |
|---|---|---|
| new lead | comment, message, form, live lead | reply within 5 minutes |
| contacted | customer answered core question | ask diagnostic questions |
| qualified | clear use case, budget, or usage volume | book diagnosis |
| diagnosed | 10-20 minute call completed | send quote within 2 hours |
| quoted | formal quote sent | confirm within 24 hours |
| contracting | package/entity/invoice confirmed | send contract and payment details |
| paid | payment received | activate and create support group |
| active | service running | weekly report and renewal alert |
| renewal/lost | upgraded, renewed, or churned | record reason |

Every CRM record needs:

`next action + responsible person + time`

No next action means it is not a real opportunity.

## API Integration Handoff

For any customer using OpenAI-compatible API access, send an integration handoff after payment and package confirmation.

Handoff must include:

- API type: OpenAI-compatible
- Base URL
- API key, masked in records
- model name
- whether streaming is supported
- budget cap
- rate limit
- allowed scenarios
- support contact
- sensitive-data warning

Use this customer explanation:

```text
只要你的工具支持 OpenAI-compatible API，一般只需要填 Base URL、API Key 和 Model Name。
如果工具要求 Base URL，填到 /v1；
如果工具要求完整 Endpoint，填到 /v1/chat/completions。
测试时不要上传客户姓名、电话、地址、订单号、邮箱、支付信息或账号密码。
```

For programmers, send the integration guide and ask them to test `/chat/completions` with a non-sensitive prompt before connecting production data.

Invoice confirmation script:

```text
我们可以开普票，也可以开专票。你们如果要走公司采购，我这边先确认三个信息：
第一，付款主体和开票主体是否一致；
第二，需要普票还是专票；
第三，开票项目按实际服务内容走，比如技术服务、信息技术服务、软件服务或实施服务，具体以财务确认口径为准。
确认后我把报价、合同、付款信息和开票信息表一起发你。
```

| Amount | Rule |
|---:|---|
| <= RMB 29,800 | 100% prepaid |
| RMB 29,800-98,000 | 100% prepaid, formal contract |
| >= RMB 98,000 | normally 100% prepaid; at most 80% prepaid + 20% milestone with approval |
| old-customer monthly billing | only after 3 successful prepaid cycles and credit review |

## Low-Price Trial Offer

Use low-price trials to reduce first-order friction:

| Offer | Price | How To Position |
|---|---:|---|
| Micro connectivity check | RMB 9.9-39 | 1-2 day demo-only validation, not real raw quota; RMB 2 only as invite-only coupon |
| Light trial | RMB 2,980 | 7-day enterprise validation, 1 use case, simple usage record |
| Standard trial | RMB 4,980 | 14-day small-team validation, basic report and review |
| Enterprise trial | RMB 9,800 | formal trial with contract/invoice and fuller support |

Micro-trial rule:

```text
2 元这种只能做邀约连通性验证，不适合公开投放。
现在实际成本按 3 折算，30 美元面值的内部成本约 10.8 元。
所以 9.9 可以做 1 天受控体验，但不是裸额度包：
只跑 1 个场景，不导出 API key，不支持批量任务，异常高频自动停止。
如果客户要真实团队试跑，引导到 2,980 或 4,980 企业试用包。
```

Micro-trial configuration:

```text
9.9 元/19.9 元/39 元微体验：
- 24-48 小时有效；
- 只开放 1 个场景；
- 9.9 可给最高 USD 30 面值体验预算，但必须由后台控制；
- 不给 API key；
- 不支持批量任务；
- 不支持文件上传；
- 一个手机号/公司/设备/IP 集群限一次；
- 异常高频自动停止；
- 需要合同/普票/专票的客户，转 399 诊断或 2,980 企业试用包。
```

Trial close script:

```text
你不用一上来买 29,800。
第一次合作可以先用 2,980 或 4,980 的企业试用包。
它的目的不是长期使用，而是验证 7-14 天：场景能不能跑通、用量大概多少、报表是否能给内部审批用。
如果试用后 7 天内升级到 29,800 增长包，试用费可以抵扣一部分正式服务费。
```

Trial boundary script:

```text
低价试用包会严格限制范围：一个业务场景、固定服务期、有限用量、一次开通指导。
不包含多部门权限、复杂 API 集成、长期 SLA 或无限技术支持。
如果你们是生产系统或多人团队长期使用，建议直接上 29,800 增长包。
```

## Invoice-Based Objection Handling

When the customer compares only raw price:

```text
如果只比裸用量，市面上一定有人更便宜。
但企业采购看的不是单价一个点，而是合同、普票/专票、预算上限、用量报表、异常预警、售后响应和后续复盘。
你们如果要给财务、老板或采购解释，这套服务比零散买额度更容易过内部流程。
```
