# 21. 个人10%-15%提成下的50万目标打法

## 结论

如果你的提成是实收回款的 10%-15%，并且你个人目标是年底前拿到 RMB 500,000，那么不能再按“公司净利润 50 万”的 200 万回款模型来执行。

要按个人收入倒推：

| 提成比例 | 个人拿到 RMB 500,000 需要的实收回款 |
|---:|---:|
| 10% | RMB 5,000,000 |
| 12% | RMB 4,166,667 |
| 15% | RMB 3,333,333 |

执行口径：

```text
保底按 10% 提成算：年底前 RMB 5,000,000 实收回款。
15% 只能当奖励，不能当计划。
```

## 为什么必须按500万回款管

因为实际销售里会有：

- 退款
- 折扣
- 客户分期
- 部分订单不计提成
- 提成延迟发放
- 低价单占用时间
- 企业客户年底流程拖延

所以个人 50 万目标要按这条线管：

```text
目标回款：RMB 5,000,000
冲刺回款：RMB 5,500,000-6,000,000
最低可接受回款：RMB 4,200,000，前提是平均提成接近 12%
```

## 回款结构

低价包只能获客，不能承担收入主力。500 万回款应该这样拆：

| 产品线 | 数量 | 单价 | 回款 |
|---|---:|---:|---:|
| 9.9/19.9/39 微体验 | 500 | RMB 39 | RMB 19,500 |
| 电商小包/任务卡 | 150 | RMB 999 | RMB 149,850 |
| 2,980/4,980/9,800 试用包 | 100 | RMB 4,980 | RMB 498,000 |
| 29,800 增长包 | 70 | RMB 29,800 | RMB 2,086,000 |
| 98,000 团队包 | 14 | RMB 98,000 | RMB 1,372,000 |
| 300,000+ 企业包 | 3 | RMB 300,000 | RMB 900,000 |
| 合计 | - | - | RMB 5,025,350 |

这张表说明一件事：

> 真正决定你能不能拿到 50 万提成的，不是 9.9 卖了多少，而是 29,800、98,000、300,000+ 能不能持续成交。

## 每周硬指标

从 8 月开始，每周至少要看这几个数：

```text
1. 新有效线索：80-150
2. A 类线索：20-40
3. 诊断/试用沟通：10-20
4. 29,800 以上报价：5-10
5. 29,800 以上成交：1-3
6. 本周实收回款：150,000-250,000
7. 本周个人提成测算：15,000-37,500
```

如果连续两周没有 29,800 以上成交，就不要继续优化 9.9 文案，要立刻回到企业线索、渠道、转介绍和老客户升级。

## 每日动作

每天要做四件事：

```text
1. 获客：
   - 发 1 条 9.9/39 低门槛体验内容
   - 发 1 条企业预算/发票/报表内容
   - 发 1 条电商素材/SEO/出海 API 内容

2. 私信：
   - 低预算客户推 39/99/199
   - 有发票需求客户推 2,980/4,980/9,800
   - 有团队/持续需求客户推 29,800
   - 有多部门/系统/API需求客户铺垫 98,000

3. 报价：
   - 每天至少发出 2 个正式报价
   - 每天至少推进 1 个 29,800 以上机会
   - 每天复盘所有“只问价不付款”的原因

4. 提成表：
   - 今日回款
   - 累计回款
   - 按 10% 预计提成
   - 按 12% 预计提成
   - 按 15% 预计提成
   - 距离 500,000 提成还差多少
```

## 销售优先级

| 客户类型 | 优先级 | 原因 |
|---|---:|---|
| 明确要合同、普票/专票、团队使用 | S | 容易上 29,800/98,000 |
| 出海电商，有 API/素材/SEO/客服需求 | A | 可组合服务，客单价高 |
| AI 工具团队/开发者团队 | A | 用量稳定，有续费可能 |
| 电商小店但持续上新 | B | 可从 39/99/199 升到 999/4,980 |
| 个人用户，只问最低价 | C | 可以自动化成交，不要花太多人工 |
| 要共享账号、无限量、绕规则 | D | 拒绝 |

## 话术

当客户嫌贵：

```text
你不用一上来买大包。
如果只是看能不能跑，可以先用 9.9/39 的体验；
如果是小团队验证，可以用 2,980 或 4,980；
如果你们需要公司付款、合同、普票/专票、用量报表和持续支持，才建议看 29,800。
我先按你的场景判断，不会硬推最大包。
```

当客户有公司采购需求：

```text
如果要走公司采购，我建议不要按零散额度买。
正式方案会包含：合同、普票/专票、预算上限、用量记录、交付清单和服务边界。
你们先跑 7-14 天试用包，确认场景和用量后，再决定是否上 29,800 增长包。
```

当客户适合 98,000：

```text
你们这个已经不是单次试用了。
如果涉及多人、多个场景、持续调用、财务报销和月度复盘，98,000 团队包会比每次零散加购更好管理。
它买的不是裸额度，而是 90-180 天的团队级用量管理、预算预警、报表、复盘和支持。
```

## 红线

为了拿提成，也不要碰这些：

- 不卖共享 key
- 不承诺无限量
- 不讲半官方/内部渠道
- 不承诺不封、不限流、永远稳定
- 不做假评价、假订单、虚假宣传
- 不对客户敏感数据做无边界处理
- 不为了低价客户牺牲高价客户跟进时间

## 一句话

```text
你个人要拿 50 万提成，就要按 500 万实收回款打，不要被 9.9 的热闹迷惑；每天都要把线索往 29,800、98,000、300,000+ 上推进。
```
