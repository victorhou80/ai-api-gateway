# 12. Ecommerce Lightweight Customer Playbook

## Core Judgment

电商客户确实可能用不了 29,800、98,000 这种企业用量包。

但这不代表电商客户不值得做，而是销售方式要换：

> 不卖大额度，不卖 token 面值，卖「电商任务包 + 小额度托管 + 可开票服务」。

电商客户真正愿意付钱的，不是“我有多少 token”，而是：

- 多少个 SKU 能快速写好标题、卖点、详情页初稿
- 客服常见问题能不能变成标准回复
- 直播脚本、短视频脚本、投流素材能不能稳定产出
- 新品上架、活动大促、客服培训能不能省人
- 公司付款、普票/专票、交付清单能不能给老板和财务看

所以电商线的产品原则是：

- 小店不推大包，先推 399、999、1,999、2,999
- 有团队、有发票、有持续上新，推 4,980 或 9,800
- 多店铺、多客服、多内容人员，才推 29,800
- 永远不要说“无限写”“无限额度”“包爆单”
- 每个小包都要写清楚 SKU 数、脚本数、修改轮次、服务时间、用量上限

## Why Ecommerce Needs A Separate Ladder

原企业包的逻辑是“用量管理”。

电商小客户的逻辑是“任务交付”。

如果电商老板说：

> 我们用不了那么多。

正确回应不是继续解释 token 多便宜，而是说：

```text
对，小店确实不适合一上来买大额度。
电商客户我们一般不按大用量包卖，而是按任务来做：
比如 10 个 SKU 标题卖点、客服话术、短视频脚本、直播脚本。
你们先用 399 或 999 跑一个小场景，确认有用再升级。
```

## Affordable Version For Very Small Stores

有些电商客户连 399/999 都会觉得贵。这类客户可以接，但只能用“平价任务卡”，不能用开放式服务。

Recommended ladder:

| Product | Price | Delivery | Boundary |
|---|---:|---|---|
| 商品小样 | RMB 9.9 | 1 个商品标题 + 3 个卖点 + 1 条客服回复 | 只展示，不修改 |
| 单品快写卡 | RMB 39 | 1 个 SKU 标题 3 版、卖点 5 条、详情页结构、短视频开头 3 条 | 表单下单，0 次修改 |
| 爆品文案卡 | RMB 99 | 1 个重点商品：标题、主图文案、详情页结构、FAQ、短视频脚本 | 1 次小修，不电话 |
| 小店上新卡 | RMB 199 | 5 个 SKU 标题/卖点，10 条 FAQ，5 条短视频脚本 | 1 个类目，1 轮统一修改 |
| 月度自助卡 | RMB 599/month | 每月 20 个任务点，异步交付 | 不开会，不接系统，不滚动 |

Sales line:

```text
如果你觉得 399/999 也高，可以先用平价任务卡。
39 试 1 个商品，99 做 1 个重点商品，199 做 3-5 个商品，599 适合每月持续上新。
平价卡都是表单下单、异步交付，不含电话诊断和复杂修改，所以价格才能低。
```

Rules:

- below RMB 399, no call
- below RMB 399, no strategy diagnosis
- below RMB 399, no custom workflow
- below RMB 399, no unlimited revision
- below RMB 399, no API key or raw usage access
- if the customer needs invoice/contract/procurement support, push RMB 999 or RMB 4,980+

## Product Design Rule

电商轻量包必须按“交付物”定价，而不是按 token 定价。

不要说：

```text
给你多少美元 token。
```

要说：

```text
帮你完成 10 个 SKU 的标题、卖点、FAQ 和短视频脚本初稿。
```

原因：

- 客户听得懂 SKU、脚本、客服话术，听不懂 token 消耗
- 即使实际用量成本是 3 折，低价客户真正消耗的是沟通、修改和交付时间，必须靠服务费和流程化交付赚钱
- 小客户如果只买便宜额度，会消耗大量客服时间
- 用交付物设边界，才能控制成本和修改次数

## Exact Reply: "We Cannot Use That Much"

```text
对，你这个判断是对的。
如果你们是普通电商小店，不建议一上来买 29,800 或 98,000 的企业包。

电商客户我们一般按任务来做，不按大额度来卖：

1. 399：先诊断你们店铺最适合用 AI 的 1-2 个环节；
2. 999：跑 7 天小店上新包，做 10 个 SKU 的标题、卖点、客服回复和短视频脚本；
3. 1,999/2,999：适合一批 SKU、客服话术或直播短视频素材；
4. 4,980：适合小团队试跑 14 天，并且可以走公司付款、普票/专票；
5. 9,800：适合持续上新或客服团队，一个月轻托管。

你不用为了“额度”买单，先按你们这周最痛的任务买就行。
```

## Ecommerce Objection Handling

### "AI 写的东西能直接用吗？"

```text
不建议完全不看就直接用。
我们的交付定位是 AI 初稿 + 结构整理 + 人工质检，不承诺完全替代运营判断。
尤其是功效、价格、活动、售后政策这些内容，必须由你们确认。
```

### "能保证转化吗？"

```text
不能承诺转化率或爆单。
我们能保证的是按约定交付标题、卖点、脚本、客服话术和修改轮次。
转化还受产品、价格、评价、投流、人群、页面承接影响。
```

### "我只要很少一点，能不能便宜点？"

```text
可以选更小的任务包，但不建议把服务拆成无限小。
因为真正成本不是 token，而是沟通、整理、质检和修改。
如果只是看效果，可以先做 399 诊断或 999 小店上新包。
```

### "我自己用 AI 也能写，为什么找你？"

```text
如果你会写提示词、会整理素材、会判断平台风险，自己做当然可以。
我们适合的是没时间反复调、希望有模板、有交付清单、有修改边界、还能公司付款开票的客户。
```

### "可以先免费做一个吗？"

```text
可以做极小样例，但免费样例只用于判断风格，不做完整交付。
如果你要完整 10 个 SKU 或一套客服话术，就走 999/2,999 的任务包。
这样双方边界清楚，也能保证排期。
```

## Delivery SOP For Ecommerce Packages

### Step 1: Confirm Scope

Collect:

- platform
- category
- store link
- SKU list
- product images or existing product copy
- target customer
- tone preference
- prohibited claims
- invoice need
- delivery deadline

### Step 2: Set Boundaries

Before payment, confirm:

- number of SKUs
- number of scripts
- number of FAQ items
- number of revision rounds
- service period
- format of final delivery
- whether invoice is needed
- no performance guarantee
- no fake review, fake order, false claim, or prohibited wording

### Step 3: Take Payment

Use this message:

```text
确认一下，本次是【套餐名】，金额【价格】。
交付包含【SKU/脚本/话术数量】，服务周期【时间】，修改【次数】轮。
付款后开始排期；如需普票/专票，请把开票信息一起发我。
```

### Step 4: First Sample

Deliver 1 SKU or 1 script first:

```text
我先给你看 1 个样例，主要确认风格和信息准确性。
你只需要反馈三点：信息是否准确、语气是否合适、有没有不能写的词。
确认后我再批量做后面的内容。
```

### Step 5: Batch Delivery

Deliver with a table:

| Field | Content |
|---|---|
| SKU / Topic | product name or topic |
| Title | suggested title |
| Selling Points | 3-5 bullet points |
| Detail Structure | section outline |
| FAQ / Reply | customer-service answer |
| Risk Note | terms that need customer confirmation |

### Step 6: Review And Upsell

After delivery:

```text
这次交付已经完成。
我建议你们接下来观察 3 件事：
1. 运营改稿时间有没有减少；
2. 客服重复问题有没有减少；
3. 上新速度有没有提升。

如果这三个有明显改善，下次就不建议继续零散买，可以升级到 4,980 试用包或 9,800 月度轻托管。
```

## Audit Rules

The manager should reject the deal if:

- customer asks for fake reviews, fake orders, false advertising, or prohibited claims
- customer wants unlimited revisions for a low-ticket package
- customer refuses to provide product information but demands a guaranteed result
- expected support time exceeds package margin
- package has no clear SKU/script/FAQ count
- salesperson promises traffic, conversion, GMV, ranking, or platform approval
- salesperson exposes API key or raw upstream access

## Margin Protection

For each ecommerce package, track:

```text
Gross margin = price - token cost - estimated labor cost - platform/payment/tax cost
```

Recommended internal labor caps:

| Product | Max Human Time |
|---|---:|
| RMB 99-199 template pack | 0-10 minutes |
| RMB 399 diagnosis | 45 minutes |
| RMB 999 upstart package | 2 hours |
| RMB 1,999 SKU sprint | 4 hours |
| RMB 2,999 service/script package | 5 hours |
| RMB 4,980 standard trial | 8 hours |
