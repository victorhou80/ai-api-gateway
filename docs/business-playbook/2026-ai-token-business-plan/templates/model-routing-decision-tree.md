# 模型路由决策树

用途：把“模型路由”讲清楚。客户不关心神秘术语，关心准确、稳定、成本和失败时怎么办。

承接产品：399 API 诊断、4,980 API 路由试跑、9,800 出海模型包、29,800 工作流包。

## 1. 决策树

```text
第 1 步：是否包含敏感数据？
是 -> 先脱敏或拒绝进入模型。
否 -> 第 2 步。

第 2 步：任务价值高不高？
高价值任务，如英文 listing、核心广告语、技术问答 -> 优先高质量模型。
低价值批量任务，如标题初稿、FAQ 草稿 -> 优先低成本/高速模型。

第 3 步：是否要求低延迟？
要求低延迟 -> 选快模型或流式输出。
不要求低延迟 -> 选质量更稳的模型。

第 4 步：预算是否接近预警线？
低于 70% -> 按默认策略。
70%-85% -> 批量任务切低成本模型。
85%-95% -> 限制非核心任务。
超过 95% -> 暂停非必要调用，等待确认。

第 5 步：失败怎么办？
超时 -> fallback 到备用模型。
429 -> 排队或降并发。
输出不合格 -> 人工复核或换模型。
敏感数据 -> 阻断并提示补充脱敏。
```

## 2. 路由表

| 场景 | 默认模型 | 备用模型 | 成本等级 | 质量要求 | 延迟要求 | 失败策略 |
|---|---|---|---|---|---|---|
| 中文客服 FAQ | balanced-model-b | fast-model-c | 低 | 准确、礼貌、边界清楚 | 8s 内 | 超时切备用 |
| 英文 Amazon Listing | high-tier-model-a | balanced-model-b | 中 | 语气自然、事实准确、风险低 | 12s 内 | 人工复核 |
| TikTok Shop 脚本 | creative-model-d | high-tier-model-a | 中 | 多角度、口语化 | 15s 内 | 输出 3 版供选 |
| 批量 SKU 标题 | fast-model-c | balanced-model-b | 低 | 格式稳定、关键词覆盖 | 6s 内 | 抽样质检 |
| 技术问答 | high-tier-model-a | balanced-model-b | 高 | 逻辑清楚、不要编造 | 20s 内 | 失败转人工 |
| 敏感订单处理 | none | none | - | 不进入模型 | - | 脱敏后再处理 |

## 3. 成本控制规则

| 预算状态 | 策略 |
|---|---|
| 0%-70% | 默认路由 |
| 70%-85% | 批量任务切低成本模型，提醒客户 |
| 85%-95% | 限制非核心任务，保留核心任务 |
| 95%+ | 暂停非必要调用，确认是否加预算或降级 |

## 4. 录屏讲法

```text
模型路由不是玄学，就是四件事：
场景、成本、质量、失败策略。
高价值任务用强模型，批量任务用快模型，预算接近上限就降级非核心任务。
失败时要有 fallback，不能让生产系统直接卡死。
```
