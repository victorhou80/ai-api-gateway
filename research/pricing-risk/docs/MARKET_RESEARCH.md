# AI API 中转市场价格与风险研究

## 1. 研究问题

本研究试图回答四个可验证的问题：

1. 国内 GPT API 中转市场的公开价格区间是多少？
2. “人民币 0.3 元买官方牌价 1 美元用量”位于什么市场位置？
3. 哪些低价可能由合法或灰色资源解释，哪些价格无法由普通官方按量 API 直采解释？
4. 如何在不作无证据犯罪指控的前提下，判断线路是否适合个人试验或生产业务？

## 2. 研究边界

### 包含

- 公开网页价格；
- 站方公开资源组和模型名称；
- 第三方价格榜的价格、可用性样本和来源标签；
- OpenAI 官方标准、Batch/Flex、缓存价格作为成本锚点；
- Token 换算和商业可持续性分析；
- 防御性尽调与小额验证方法。

### 不包含

- 购买或测试黑号、黑卡、被盗 Key；
- 获取私人群、暗网或非公开供应链报价；
- 绕过上游身份验证、限流或封禁；
- 对任何经营者作刑事事实认定；
- 未经授权向中转站发送用户秘密或私有代码。

## 3. 为什么必须统一口径

中转站常见三种不同数字：

1. **充值换算**：例如 1 元换 1 站内美元，或 6.8 元换 1 站内美元；
2. **模型倍率**：例如 GPT 分组为官方数字的 0.1 倍；
3. **活动/VIP**：充值赠送、累计充值折扣或专用模型额度。

只看其中一个数字会误判。本文定义：

```text
C = 买到官方标准牌价 $1 的 Token 用量需要支付的人民币
```

例如：

- 1 元兑换 1 站内美元，模型倍率 0.30，则 `C=0.30`；
- 6.8 元兑换 1 站内美元，模型倍率 0.10，则 `C=0.68`；
- 1 元兑换 7.5 站内美元，模型倍率 1.00，则 `C≈0.1333`。

活动赠送必须单列为“阶段性有效 C”，不能与长期基础价混为一谈。

## 5. 第一方页面复核

### OneHop

OneHop 价格页当日显示：

- GPT-5.6 Sol：输入 `$0.50/M`、输出 `$3/M`；
- OpenAI 官方标准价格：输入 `$5/M`、输出 `$30/M`；
- OneHop 人民币展示按固定 `6.8` 汇率折算；
- 因此 `C=6.8×0.10=0.68`；
- 即 1 元约买到官方牌价 `$1.4706` 的用量。

页面同时出现“仅官方价 5%”横幅与“表格为官方价 10%”的冲突。本文采用可逐项计算的价格表，不把横幅的 5% 当成已确认扣费。

### 随想

随想公开模型页列的是官方牌价，并说明最终扣费还要乘控制台公开倍率。购买页要求登录，因此未获得 GPT 实时倍率。公开信息只能确认：

- 充值宣传为 1 元等于 1 站内美元余额；
- 最终价格依赖模型倍率和 VIP 折扣；
- 未登录状态无法得出唯一 C 值。

### RTOC

RTOC 第一方价格页当日可见：

- GPT 资源组倍率 `x0.06`；
- GPT Pro 资源组倍率 `x0.2`；
- GPT-5.4 输入 `0.15/M`、输出 `0.9/M`，相对于当时官方 `$2.5/$15` 为 0.06 倍；
- GPT-5.4 mini 输入 `0.045/M`、输出 `0.27/M`，同样为 0.06 倍。

该证据确认“站方确实公开了低倍率价格”，但不能独立确认支付来源、模型真实性或长期供应能力。

## 6. 极低价可能来自哪里

### 6.1 可解释但有条件的来源

- 企业预付或规模采购折扣；
- Batch/Flex 等服务层级折扣；
- 高缓存命中带来的真实输入成本下降；
- 云厂商、区域或结算货币差异；
- 新用户、创业计划或合作伙伴赠金；
- 短期获客补贴；
- 固定订阅配额被高利用率共享。

这些来源并不都能用于实时、无限、长期的标准 API。Batch/Flex、缓存和赠金都有明确适用边界。

### 6.2 灰色或高风险来源

- ChatGPT Plus/Pro/Team、Claude Max 等订阅切片；
- Codex、Kiro 或其他 IDE 内部额度逆向；
- 网页端/客户端协议逆向；
- 大量账号轮换形成号池；
- 二级、三级分销导致上游不可追踪；
- 模型名称不变但后端动态切换便宜模型；
- 缓存、reasoning 或失败请求的隐性扣费；
- 预付资金池补贴，余额兑付依赖持续充值。

### 6.3 明确违法或未经授权的可能来源

- 盗刷信用卡；
- 被盗 API Key；
- 被接管个人或企业账号；
- 伪造身份、账单地址或支付资料；
- 未经授权转售他人账户和额度。

这类情况确实可能存在，但不能仅凭价格确认。需要支付拒付、账号归属、上游账单、封禁原因、调查报告或司法材料。

## 7. 成本地板判断

按约 `1 USD≈7.2 CNY`，购买官方标准 API 牌价 `$1` 的现金成本约为人民币 7.2 元。不同 C 相对于官方现金成本为：

| C | 相当于官方现金成本 | 需要解释的折扣 |
|---:|---:|---:|
| 1.00 | 13.89% | 约 86.11% |
| 0.68 | 9.44% | 约 90.56% |
| 0.30 | 4.17% | 约 95.83% |
| 0.10 | 1.39% | 约 98.61% |
| 0.03 | 0.42% | 约 99.58% |

因此，`C≤0.30` 应触发严格的来源解释和独立验证。即便 `C=1.00`，也已远低于普通美元现金直采成本，不能仅靠“一美元数字换一人民币单位”解释上游采购。

官方 Batch/Flex 通常只能解释约 50% 的标准价差；缓存输入可能低到普通输入的约 10%，但只作用于命中的缓存输入，不能覆盖输出和所有请求。两者都不能单独解释实时、全输入输出、长期 `C=0.03–0.30` 的通用服务。

## 8. 价格不能证明什么

低价不能独立证明盗刷，高成功率也不能证明安全：

- HTTP 成功只证明请求曾得到响应；
- `response.model` 可以被网关改写；
- Token 数可以用官方 tokenizer 重新计算后伪装；
- 近期 99% 成功率不能证明账号下周不被封；
- 企业主体和发票不能自动证明某条上游线路合法；
- “官方 API”属于站方声明，除非有采购与账单证据；
- 第三方“来源标签”是线索，不是审计结论。

## 9. 商业建议

对于当前 `C=1.00` 的产品，不建议把目标设成追平极端低价。建议把核心竞争力从 Token 单价转换成可验证的信任：

1. 为每条线路记录 `source_type`、供应商主体、合同、账单和允许的转售范围；
2. 生产线只接可解释、可追责的来源；
3. 实验线使用独立域名、余额、Key、路由和风险提示；
4. 对输入、缓存读写、输出、reasoning、工具调用分别计费；
5. 公开失败请求扣费规则和退款机制；
6. 支持用户导出逐请求账单；
7. 监测模型指纹、TTFT、TPS、错误率、限流与长上下文；
8. 对余额实行隔离和最低兑付保障；
9. 不接收用户 ChatGPT Cookie、主账号密码或上游私钥；
10. 把“未做真伪检测”明确展示为未知，而不是默认通过。

## 10. 结论

`¥0.30/官方 $1 用量`确实属于高风险低价，但不是市场最低。公开报价已到约 `¥0.03/$1`。如此低的价格基本排除了“普通官方按量 API 直采再转售”的解释，却不能仅凭价格确定是盗刷；订阅切片、IDE 逆向、赠金、混池、模型替换和隐性计费都可能产生类似报价。

对正式产品而言，最重要的不是宣称“绝对没有黑号”，而是建立可审计证据链，使每条线路的来源、计费、模型、隐私、失败处理和余额责任都能被验证。
