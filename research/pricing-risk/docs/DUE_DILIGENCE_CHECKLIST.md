# 中转线路尽调与上线门禁

这份清单用于采购、接入或自营 AI API 中转线路。它不能证明绝对安全，但能把“便宜且说不清来源”转化为可审计的拒绝条件。

## A. 主体与合同

- [ ] 运营主体、收款主体、开票主体一致或关系可解释；
- [ ] 有服务协议、隐私政策、退款政策和余额处理规则；
- [ ] 合同明确上游来源类型及是否允许转售；
- [ ] 有数据处理条款和安全事件通知时限；
- [ ] 有停服、封号和余额退还责任；
- [ ] 不要求以无法追索的方式支付全部款项。

## B. 上游来源

- [ ] 区分官方 API、云厂商、订阅账号池、IDE 配额、逆向和二级分销；
- [ ] 提供脱敏采购合同、发票或上游账单样本；
- [ ] 证明账号、Key 和支付方式归属合法；
- [ ] 明确是否使用赠金、试用金或区域优惠；
- [ ] 明确是否违反上游服务条款中的共享或转售限制；
- [ ] 未披露来源不得进入生产线路。

## C. 模型真实性

- [ ] 运行多轮模型指纹与能力基准，不只看 `response.model`；
- [ ] 对流式事件、工具调用、上下文长度和输出行为做协议验证；
- [ ] 用相同 prompt 与已知官方线路做盲测；
- [ ] 对模型降级、动态路由和故障回退提供显式标记；
- [ ] 模型版本变化必须进入审计日志；
- [ ] 未完成真伪检测的线路只允许实验流量。

## D. 计费真实性

- [ ] 输入、缓存写、缓存读、输出、reasoning 分项记录；
- [ ] 用本地 tokenizer 和官方账单抽样对账；
- [ ] 验证失败、取消、超时和重试是否重复扣费；
- [ ] 验证长上下文和 Priority/Flex/Batch 是否切换价格；
- [ ] 充值倍率、模型倍率、VIP 和赠送分别展示；
- [ ] 用户可导出逐请求账单和余额流水。

## E. 稳定性与容量

- [ ] 连续测试至少 7 天，不以单日成功率代替稳定性；
- [ ] 记录 TTFT、TPS、完整请求耗时和 P50/P95/P99；
- [ ] 记录 429、401、403、423、5xx、超时和空响应；
- [ ] 在高峰期测试并发和限流；
- [ ] 验证上游封号后是否静默切换到其他模型；
- [ ] 有故障隔离、熔断和可恢复的备用线路。

## F. 数据安全

- [ ] 默认不向未披露线路发送秘密、个人信息和客户数据；
- [ ] 不上传 ChatGPT Cookie、主账号密码或上游 API Key；
- [ ] 明确 Prompt、文件、响应、日志和计费摘要的保留时间；
- [ ] 明确数据驻留地区和分包商；
- [ ] 传输加密、密钥隔离和访问审计可验证；
- [ ] 生产流量与实验号池使用独立域名、Key、余额和日志。

## G. 财务与余额风险

- [ ] 首次只做最小金额试用；
- [ ] 不因大额折扣提前囤积不可退款余额；
- [ ] 设置单站余额上限和自动补充上限；
- [ ] 监控拒付期、账单日附近的异常封号；
- [ ] 供应商突然停服时有余额赔付或保险安排；
- [ ] 毛利模型计入支付费、失败重试、售后和坏账。

## H. 红线

出现下列任一情况，不得进入生产：

- [ ] 明示使用盗刷信用卡、被盗账号或被盗 API Key；
- [ ] 要求伪造身份、地区、账单地址或支付资料；
- [ ] 拒绝解释上游，却宣称“100% 官方无限量”；
- [ ] 阻止用户导出账单或发现 Token 虚增；
- [ ] 真伪检测显示模型替换但站方不披露；
- [ ] 数据处理政策允许出售、训练或未授权共享 Prompt；
- [ ] 支付、域名和主体频繁变更且无法解释。
