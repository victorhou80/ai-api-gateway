# 新的 API 销售工具线索

这是一套围绕 `sub2api-mod` 和 `TokLens` 搭建 AI API 销售、交付、用量对账和客户运营的资料包。

目标不是把业务包装成“便宜 token 转卖”，而是包装成更适合企业客户接受、也更容易签合同和开发票的服务：

> AI API 接入托管 + 用量看板 + 预算控制 + 技术接入支持 + 合同发票。

## 这套东西解决什么

1. 客户怎么接 API。
2. 客户怎么拿到自己的 API Key。
3. 客户怎么查用量、查模型、查消耗。
4. 我们怎么控制试用包、轻量包、企业包额度。
5. 我们怎么做月度用量表、内部毛利表、销售提成表。
6. 销售怎么讲、怎么推进、怎么复盘。
7. 技术怎么部署服务器、域名、网关、客户门户。

## 推荐系统组合

| 模块 | 项目 | 作用 |
|---|---|---|
| API 网关后台 | `alphane-ai/sub2api-mod` | 发 Key、接客户请求、调度上游模型、限流、计费、记录用量 |
| 客户用量门户 | `alphane-ai/toklens` | 客户查 Key、看用量、看 Dashboard、看请求明细 |
| 数据库 | PostgreSQL | 用户、Key、用量、套餐、订单、配置 |
| 缓存/限流 | Redis | 限流、并发、调度缓存 |
| 反向代理 | Caddy/Nginx | HTTPS、域名分流 |

## 第一阶段最小上线形态

第一阶段不需要完整 SaaS 商城，一台服务器就可以跑通 MVP：

```text
一台海外 VPS / 云服务器
  ├─ sub2api-mod: API 网关 + 管理后台
  ├─ TokLens: 客户用量看板
  ├─ PostgreSQL
  ├─ Redis
  └─ Caddy/Nginx: HTTPS + 反向代理
```

建议域名：

```text
api.example.com       客户 API Base URL
portal.example.com    客户用量看板
admin.example.com     内部后台，可选，建议限制访问
```

## 关键原则

1. 对外卖“AI API 接入托管服务”，不要卖“低价 token”。
2. 对客户强调“可查用量、可控预算、可签合同、可开发票、有人支持”。
3. 上游 Key 永远不交给客户，客户只拿下游 API Key。
4. 试用包必须限制有效期、并发、模型范围，避免被薅。
5. 企业包必须包含合同、发票、月报、接入支持，不只卖额度。
6. 所有公开宣传避免“官方内部、无限量、不封号、绕过限制、保证 ROI”等表述。
