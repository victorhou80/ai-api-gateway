# 07. 合规、风控和宣传边界

## 基本原则

这套业务应对外表达为：

```text
AI API 接入托管服务
模型用量管理服务
企业 AI 接入与预算控制服务
```

不要表达为：

```text
低价 token 倒卖
官方内部渠道
无限量 API
绕过限制
保证不封号
```

## 宣传禁区

公开平台不要写：

1. 官方内部渠道。
2. 半官方渠道。
3. 不封号。
4. 无限量。
5. 绕过限制。
6. 保证 ROI。
7. 保证爆单。
8. 官方最低价。
9. 可规避风控。
10. 共享官方账号。

## 推荐表达

可以写：

1. 标准 API 接入。
2. 兼容 OpenAI/Claude 常见接口。
3. 用量可视化。
4. 预算可控。
5. 支持企业合同和发票。
6. 提供接入支持。
7. 支持电商内容生产场景。
8. 支持开发者工具接入。

## 客户数据安全

注意：

1. 不要在截图中展示完整 API Key。
2. 不要在聊天记录里发完整 Key，必要时用一次性文档或后台交付。
3. Request Capture 可能包含客户请求内容，必须限制内部访问权限。
4. 客户月报只显示 Key 片段。
5. 服务器日志不能打印完整 Authorization header。
6. PostgreSQL 和 Redis 不开放公网。
7. 管理后台必须强密码和 TOTP。

## 上游资源合规

使用任何上游 API、OAuth 或账号资源前，应确认：

1. 是否允许二次分发。
2. 是否允许商用托管。
3. 是否允许作为 API 网关转发。
4. 是否有地域、行业、内容限制。
5. 是否要求终端客户遵守额外条款。

如果不确定，不要在销售材料里承诺“官方、稳定、不限、永久”。

## 发票和合同表述

建议合同/发票服务名使用：

```text
AI API 接入技术服务
AI 模型接入托管服务
软件技术服务费
数据处理技术服务费
企业 AI 应用接入服务
```

具体税目和开票内容以财务/税务意见为准。

## 试用包风险控制

试用包必须有：

1. 有效期。
2. 限购。
3. 并发限制。
4. 模型范围限制。
5. 高成本功能关闭。
6. 异常用量可暂停。
7. 不承诺正式 SLA。

推荐：

```text
9.9 元试用包，24 小时有效，每个主体限购一次，仅用于接入体验和轻量场景测试。
```

## 企业客户风险控制

企业客户合同里应明确：

1. 服务内容。
2. 额度口径。
3. 用量查询方式。
4. 超额处理方式。
5. 发票类型。
6. 技术支持边界。
7. 不可用于违法违规内容。
8. 不承诺第三方模型永久可用。
9. 异常情况的处理方式。
