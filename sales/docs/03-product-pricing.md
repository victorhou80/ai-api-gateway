# 03. 产品包、价格和额度设计

## 定价基本逻辑

已知业务参数：

```text
实际成本：约 3 折
个人提成：10%-15%
可开发票：普票、专票
目标：年底前 50 万纯利润
```

定价不能只按“token 差价”讲，要按“服务组合”讲：

```text
API 接入 + 用量看板 + 技术支持 + 预算控制 + 合同发票 + 月报。
```

## 9.9 试用包配置

目的：低门槛获客，不追求单包利润。

建议配置：

| 项目 | 配置 |
|---|---|
| 售价 | 9.9 元 |
| 有效期 | 24 小时 |
| 标称体验额度 | 可写“最高约 $30 模型调用体验额度”，内部按实际策略限制 |
| 并发 | 1 |
| RPM | 30-60 |
| 模型 | 只开放低成本/轻量模型 |
| 场景 | 商品标题、五点描述、SEO 词、客服回复 |
| 限购 | 每企业/手机号/微信/邮箱限购 1 次 |
| 发票 | 默认不开票，升级正式包可抵扣 |
| 转正权益 | 24 小时内升级可抵扣 9.9 元 |

注意：如果给 `$30` 标称额度，必须用模型范围、并发、有效期和限购控制风险。

## 企业启动包 9800

这类产品必须讲清楚里面包含什么：

| 模块 | 内容 |
|---|---|
| API 接入额度 | 按合同约定额度 |
| 专属客户 Key | 至少 1 个生产 Key + 1 个测试 Key |
| 用量看板 | TokLens 账号 |
| 技术接入 | 1 次远程接入指导 |
| 预算控制 | 月预算、超额提醒、可暂停 |
| 用量报表 | 月度 Excel/PDF |
| 合同发票 | 可签合同，可开普票/专票 |
| 售后支持 | 工作时间技术支持 |

销售表达：

```text
9800 元不是买一串 Key，而是买一套可对账、可控预算、可交付给技术团队的 AI API 接入服务。
```

## 企业年度包 98000

建议包含：

| 模块 | 内容 |
|---|---|
| 专属分组 | 独立 enterprise group |
| 独立预算 | 月度/季度预算 |
| 高并发 | 按合同配置 |

| 月度复盘 | 每月用量报告 + 优化建议 |
| 技术支持 | 专属群、优先响应 |
| 发票合同 | 专票/普票 |
| SLA | 可写“尽力保障 + 故障响应”，不要承诺绝对不宕机 |

## 报价注意事项

不要写：

```text
官方内部价
无限量
永久免费
不封号
保证效果
保证 GMV
官方 token
```

可以写：

```text
企业 API 接入托管
模型用量管理
预算可控
可查明细
可开票
支持 OpenAI/Claude 兼容接口
提供接入支持
```
